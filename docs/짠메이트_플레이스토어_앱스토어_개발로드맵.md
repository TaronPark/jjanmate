# 짠메이트 플레이스토어·앱스토어 개발로드맵

> 작성일: 2026-08-02
> 본 문서는 「짠메이트 MVP 개발로드맵 v2」10단계(QA + CBT 재준비) 이후에 이어지는 스토어 배포 전환 계획입니다. 실제 착수 시점은 10단계 결과를 확인한 뒤 재확정한다는 전제로 작성되었습니다(사용자 확정, 2026-08-02). Apple Developer Program 신청 1건만 예외적으로 지금부터 병행 가능합니다.

## 결정 배경 요약

- 플레이스토어를 먼저 완결하고 그다음 앱스토어를 진행하는 순서로 확정(2026-08-02 논의).
- 공통 PWA 기반은 처음부터 애플의 더 엄격한 심사 기준(가이드라인 4.2)을 만족하도록 설계하기로 함 — 나중에 앱스토어용으로 다시 손대는 이중작업을 피하기 위함.
- 앱스토어 전환을 위한 실제 엔지니어링 착수는 10단계(QA+CBT) 결과를 본 이후로 미루기로 함 — CBT는 스토어 배포 여부와 무관하게 먼저 진행 가능하고, CBT 결과에 따라 제품 요구사항 자체가 바뀔 수 있기 때문. 단, Apple Developer Program 계정 신청은 이 의존관계가 없어 지금 바로 시작해도 무방함(조직 계정은 D-U-N-S 번호 확보에만 1~2주가 걸려 병목이 되므로 선착수 권장).

## 현재 상태 진단 (2026-08-02 확인)

짠메이트는 현재 일반 Next.js 웹앱 상태이며, PWA로서의 최소 요건(manifest.json, 서비스워커, 설치 아이콘 세트)이 아직 하나도 구현되어 있지 않음을 코드베이스에서 확인함(`public/manifest.json`, 서비스워커 파일, `next-pwa` 등 관련 설정 전무). 즉 스토어 전환의 첫 단계는 "PWA를 앱스토어용으로 다듬기"가 아니라 "PWA 자체를 처음부터 만들기"부터 시작해야 함.

## A단계: 공통 PWA 기반 구축 (10단계와 병행 가능)

10단계(QA+CBT) 진행과 별도로, 또는 그 직후 바로 착수 가능한 기반 작업. 플레이스토어·앱스토어 모두에 공통으로 필요함.

| 작업 | 내용 |
|---|---|
| Web App Manifest 작성 | (2026-08-08 완료) `app/manifest.ts`(Next.js 16 App Router 파일 컨벤션 — `/manifest.webmanifest`로 자동 서빙) — `public/manifest.json` 수동 배치 대신 이 방식 사용 |
| 서비스워커 구현 | (2026-08-08 완료) 수동(Vanilla) 구현으로 확정 — `next-pwa`/Serwist 모두 webpack 플러그인 기반이라 Next.js 16의 기본 번들러인 Turbopack을 지원하지 않아 배제함. `public/sw.js`에서 `/api/`·`/auth/`·HTML 내비게이션은 캐시하지 않고(미들웨어의 세션 쿠키 갱신 로직과 충돌 방지) 정적 자산만 cache-first로 처리 |
| PWA 설치 가능 조건 확인 | (2026-08-08 완료, 방식 변경) Lighthouse PWA 카테고리는 2024년에 완전히 삭제되어(재확인: Lighthouse 13.x 기준 `--only-categories`에 accessibility/best-practices/performance/seo/agentic-browsing만 존재, `pwa`·개별 PWA 감사 전부 없음) 점수로 확인할 방법이 없어졌음. 대신 브라우저가 실제로 설치 배지를 띄우는 5개 조건을 Vercel Preview 배포에서 직접 확인해 완료 기준으로 삼음: ① HTTPS(Vercel로 자동 충족) ② `manifest.webmanifest` 유효 JSON + 올바른 content-type ③ 아이콘 192/512(+maskable) 정상 서빙 ④ `/sw.js` 정상 서빙 ⑤ 서비스워커 등록 후 실제 로그인 세션 유지 확인 |
| 아이콘 세트 정리 | **(2026-08-08 완료)** 정식 브랜드 아이콘/워드마크 확정본을 반영함 — 원본은 `public/brand/icon-source.png`(512×512, 이중 테두리+"짠" 글자)·`public/brand/wordmark.png`(1254×1254, "JJanmate" 워드마크)로 보관. 이 원본을 기준으로 `public/icons/icon-192.png`, `icon-512.png`, `icon-512-maskable.png`(마스킹 안전영역 확보를 위해 콘텐츠를 62%로 축소 후 배경색(#111111) 풀블리드로 재구성)를 생성하고, 브라우저 favicon/애플 터치 아이콘도 `next/og` 코드생성 방식(`app/icon.tsx`/`app/apple-icon.tsx`, 임시용) 대신 정적 파일(`app/icon.png`, `app/apple-icon.png`, 애플 아이콘은 투명도 제거 후 180×180로 별도 생성)로 교체함. 임시 아이콘 생성 스크립트(`scripts/generate-pwa-icons.mjs`)는 더 이상 필요 없어 삭제, `public/sw.js`의 `CACHE_NAME`도 v1→v2로 올려 기존 설치 사용자의 캐시를 무효화함. 워드마크의 실제 UI(헤더 등) 반영 위치는 별도 확인 중 |
| 웹 푸시 알림 인프라(선택) | 안드로이드 TWA는 웹 푸시로도 어느 정도 대응 가능 — 우선순위는 낮음, C단계 이전에만 준비되면 됨 |
| **Apple Developer Program 신청** | **지금 바로 시작 가능(유일하게 QA/CBT 완료를 기다릴 필요 없음).** 개인 계정은 1~2일, 조직 계정은 D-U-N-S 번호 발급 절차 때문에 1~2주 소요. 사업자 형태로 운영할 계획이면 조직 계정 쪽이 유리하지만 시간이 오래 걸리므로 최우선으로 착수 권장 |

## B단계: Play Store 전환 (10단계 완료 후 착수)

Android는 TWA(Trusted Web Activity) 방식으로, 네이티브 앱 재작성 없이 PWA를 그대로 패키징할 수 있음 — 구글이 공식 권장하는 방식.

| 작업 | 내용 |
|---|---|
| TWA 패키징 | Bubblewrap 또는 PWABuilder로 PWA → APK/AAB 변환 |
| Digital Asset Links 설정 | `assetlinks.json`을 도메인에 배치해 앱-웹 소유권 상호 검증 |
| Google Play 개발자 계정 등록 | $25 1회성 비용(연 갱신 없음), 신원 확인 절차 포함 |
| 스토어 등록 자산 제작 | 앱 타이틀/짧은·긴 설명, 스크린샷, 고해상도 아이콘, 피처 그래픽 |
| Data Safety 폼 작성 | 수집 데이터 항목·목적·제3자 공유 여부 신고(2026년 기준 필수) — 기존 개인정보처리방침 내용 재활용 가능 |
| 비공개 테스트 12명 14일 | **신규 개인 개발자 계정은 프로덕션 공개 전 12명 테스터가 14일 연속 옵트인해야 함(2023.11.13 이후 생성 계정 대상, 조직 계정은 면제).** 아래 "시너지 포인트" 참고 |
| 프로덕션 심사 제출 | 비공개 테스트 완료 후 프로덕션 트랙으로 승격 신청 |

**시너지 포인트**: 10단계 CBT에서 모집하는 실사용자 테스터 중 안드로이드 기기 보유자를 플레이스토어 비공개 테스트 트랙에도 동시에 초대하면, CBT 기간과 12명·14일 요건을 겹쳐서 진행할 수 있어 별도 대기 시간을 아낄 수 있음. CBT 테스터 모집 시 이 부분을 미리 고려해두면 좋음.

## C단계: App Store 전환 (B단계 완결 후 착수)

iOS는 PWA/웹뷰를 그대로 감싸는 방식이 애플 가이드라인 4.2(Minimum Functionality)에 걸려 반려되는 경우가 흔함 — "웹사이트를 앱으로 포장한 것과 다르지 않다"는 사유. TWA 같은 공식 우회로가 없어 Android보다 실제 엔지니어링 공수가 더 필요함.

| 작업 | 내용 |
|---|---|
| Capacitor 네이티브 셸 구성 | 웹 코드를 로컬 빌드해 iOS 네이티브 셸에 임베드(서버 URL을 그대로 불러오는 방식은 푸시 알림이 동작하지 않아 반드시 로컬 임베드 방식 사용) |
| 최소 네이티브 기능 확보 | 가이드라인 4.2 통과를 위해 네이티브 탭바/제스처 내비게이션, 푸시 알림(APNs), 견고한 오프라인 처리 등 "앱다움"을 보여줄 요소 추가 |
| Xcode 빌드/서명 | Apple Developer Program 계정(A단계에서 이미 준비됨) 기반으로 인증서·프로비저닝 프로파일 설정 |
| TestFlight 베타 | 내부/외부 테스터 대상 사전 검증 |
| App Store Connect 심사 제출 | 반려 시 재제출까지 며칠~몇 주가 걸릴 수 있음을 감안해 일정에 여유를 둘 것 |
