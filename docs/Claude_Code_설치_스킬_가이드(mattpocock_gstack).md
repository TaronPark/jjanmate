# Claude Code 설치 스킬 가이드 (Matt Pocock Skills / gstack)

2026-08-08에 설치한 두 서드파티 스킬 팩을 정리한 문서입니다. "이런 게 있었지, 근데 정확히 뭐하는 스킬이었지?" 싶을 때 찾아보는 용도입니다.

---

## 0. 적용 범위가 다르다는 것부터

두 팩은 설치 위치가 다르고, 그래서 **적용 범위**도 다릅니다.

| | 설치 위치 | 적용 범위 |
|---|---|---|
| **Matt Pocock Skills** | `jjanmate-app/.agents/skills/` (프로젝트 로컬) | **이 프로젝트 폴더에서만** 동작 |
| **gstack** | `~/.claude/skills/` (전역) | **앞으로 여는 모든 프로젝트**에서 동작 |

즉 다른 프로젝트를 열면 Matt Pocock 스킬들은 안 보이지만, gstack 스킬들은 계속 보입니다.

스킬 이름이 일부 겹칩니다 (`review` 계열이 양쪽에 있음). 헷갈리면 원하는 스킬 이름을 명시해서 부르는 게 안전합니다 (예: "code-review 스킬로 리뷰해줘").

## 1. Matt Pocock Skills (34개, 프로젝트 로컬)

기획→구현→리뷰 엔지니어링 워크플로우와 글쓰기 계열 스킬 모음입니다.

### 기획 / 스펙 / 티켓

| 스킬 | 역할 | 언제 쓰나 |
|---|---|---|
| `to-spec` | 지금까지의 대화를 스펙으로 정리해 이슈 트래커에 발행 (인터뷰 없이 종합만) | 이미 충분히 논의한 내용을 문서화하고 싶을 때 |
| `to-tickets` | 플랜/스펙/대화를 tracer-bullet 티켓들로 분할, 티켓 간 블로킹 관계까지 표시해서 발행 | 큰 작업을 실행 가능한 작은 단위로 쪼개고 싶을 때 |
| `wayfinder` | 한 세션에 못 담을 만큼 큰 작업을 결정 티켓들의 지도로 계획하고 하나씩 풀어나감 | 여러 세션에 걸친 대형 작업을 시작할 때 |
| `triage` | 이슈/외부 PR을 분류 → 검증 → (필요시) grill → 에이전트용 브리프 작성까지 상태 머신으로 이동 | 밀린 이슈함/PR을 정리할 때 |

### 구현

| 스킬 | 역할 | 언제 쓰나 |
|---|---|---|
| `implement` | 스펙/티켓 기반으로 실제 구현 | 스펙이 이미 있고 코딩을 시작할 때 |
| `tdd` | 테스트 주도 개발 (red-green-refactor), 통합 테스트 작성 | 테스트부터 먼저 쓰고 싶을 때 |
| `codebase-design` | deep module 설계를 위한 공통 개념/용어 (인터페이스 개선, seam 위치 결정) | 모듈 인터페이스를 다듬거나 테스트/AI 친화적으로 바꿀 때 |
| `improve-codebase-architecture` | 코드베이스에서 deepening 기회를 스캔해 HTML 리포트로 제시, 고른 항목을 grill | 아키텍처 개선 지점을 찾고 싶을 때 |

|---|---|---|
| `code-review` | 특정 지점 이후 변경사항을 Standards(코딩 표준 준수) / Spec(원래 요구사항 충족) 두 축으로 병렬 서브에이전트 리뷰 | 브랜치/PR/작업 중인 변경사항을 리뷰할 때 |
| `diagnosing-bugs` | 어려운 버그·성능 회귀를 위한 진단 루프 | "디버그해줘", 뭔가 깨지거나 느려졌을 때 |

## 2. gstack (54개, 전역 — 모든 프로젝트에 적용)

Y Combinator 대표 Garry Tan이 만든 풀스택 개발 워크플로우 스킬 모음입니다 (`github.com/garrytan/gstack`). 기획 리뷰부터 QA, 디자인, 배포, iOS, 보안까지 폭넓게 커버합니다.

### 라우터 / 업그레이드

| 스킬 | 역할 | 언제 쓰나 |
|---|---|---|
| `gstack` (호출명 `_gstack-command`) | gstack 스킬 모음 전체의 라우터 — 어떤 스킬을 써야 할지 판단 | gstack 관련 요청인데 구체적으로 어떤 스킬인지 모를 때 |
| `gstack-upgrade` | gstack을 최신 버전으로 업그레이드 | "gstack 업그레이드해줘" |

### 기획 / 플랜 리뷰

| 스킬 | 역할 | 언제 쓰나 |
|---|---|---|
| `spec` | 모호한 의도를 5단계로 정밀하고 실행 가능한 스펙으로 전환 | 아이디어를 구체적인 스펙으로 만들 때 |
| `autoplan` | CEO/디자인/엔지니어링/DX 리뷰 스킬 4개를 순서대로 읽어와 6가지 결정 원칙으로 자동 실행하는 리뷰 파이프라인 | 플랜을 여러 관점에서 한 번에 검토하고 싶을 때 |
| `plan-ceo-review` | CEO/창업자 시점의 대화형 플랜 리뷰 | 사업적 관점에서 플랜을 점검할 때 |
| `plan-design-review` | 디자이너 시점의 대화형 플랜 리뷰 | 디자인 관점에서 플랜을 점검할 때 |
| `plan-devex-review` | 개발자 경험 관점의 대화형 플랜 리뷰 | DX 관점에서 플랜을 점검할 때 |
| `plan-eng-review` | 엔지니어링 매니저 시점의 플랜 리뷰 | 기술적 리스크 관점에서 플랜을 점검할 때 |
| `plan-tune` | gstack의 질문 민감도 + 개발자 성향을 자체 튜닝 (관찰 기반) | (내부적으로 다른 리뷰 스킬을 보조) |
| `office-hours` | YC Office Hours 스타일 상담 (2가지 모드) | 창업자 관점의 조언이 필요할 때 |

### 브라우저 / QA

| 스킬 | 역할 | 언제 쓰나 |

| `benchmark` | browse 데몬을 이용한 성능 회귀 감지 | 성능 저하 여부를 확인할 때 |
| `benchmark-models` | gstack 스킬들에 대한 크로스 모델 벤치마크 | 모델별 성능을 비교할 때 |

## 3. 주의해서 써야 할 스킬

아래 스킬들은 강한 권한을 쓰거나 되돌리기 어려운 동작을 포함합니다. 실행 전에 한 번 더 생각해보는 게 좋습니다.

- **`setup-browser-cookies`** — 실제 사용하는 크롬 브라우저의 쿠키(로그인 세션 포함)를 가져옵니다. 어떤 도메인의 쿠키를 가져오는지 확인하고 필요한 것만 허용하세요.
- **`ship`, `land-and-deploy`** — git push, PR 생성, VERSION/CHANGELOG 커밋 등 되돌리기 어려운 동작을 포함합니다. 이 저장소에서는 [CLAUDE.md](../CLAUDE.md)의 git 안전 원칙(강제 push 금지, 명시적 확인 등)이 우선합니다.
- **`cso`, `guard`, `careful`** — 보안/제한 모드이지만, 이 자체가 시스템을 바꾸는 동작(훅 설치 등)을 할 수 있으니 무엇을 바꾸는지 확인하세요.
- **`codex`** — 외부 OpenAI Codex CLI를 호출하는 래퍼입니다. Codex CLI가 별도로 설치·인증되어 있어야 정상 동작합니다.
- **`git-guardrails-claude-code`** (Matt Pocock 쪽) — Claude Code 훅을 설정합니다. 이 저장소의 `.claude/settings.json`을 건드리는 작업이니 기존 설정과 충돌하지 않는지 확인 후 적용하세요.

## 4. 참고

- gstack은 **전역 설치**라 이 문서를 다른 프로젝트를 열고 봐도 gstack 스킬들은 그대로 사용 가능합니다. Matt Pocock 스킬들은 이 프로젝트(`jjanmate-app`)에서만 보입니다.
- 스킬 이름이 겹치는 경우(`review`류)가 있어 자동 트리거가 헷갈릴 수 있습니다 — 원하는 스킬을 확실히 쓰려면 이름을 직접 언급하세요.
- 설치/트러블슈팅 과정(bun 설치, PowerShell 재설치 등)은 이 문서에는 담지 않았습니다. 필요하면 해당 대화 이력을 참고하세요.
