## 1. 시드 데이터 재구성 — 인서트/셋업 완료, 런칭일 대기 중

- **현황**: 사용자가 직접 작성한 400개 세이드 콘텐츠(`짠메이트_시드콘텐츠_400개_작성템플릿.xlsx` 기반)를 `seed_contents_pool`에 전량 인서트 완료(2026-08-02). 룸별 분포는 자취룸68/C발비용68/식비절약68/직장생활68/짠수다64/티끌모으기64 = 총 400개로 확인됨. 시드 페르소나도 30명 → 80명으로 확장 완료.
- **결정 (2026-08-02)**: `app/api/cron/seed-drip/route.ts`를 v1과 동일한 테이퍼링(1~7일차 30개/일 → 8~14일차 10개/일 → 15일차~ 2개/일, 룸별 잔여 풀 비례 배분, 8/12/18/23시 KST 시간대별 가중 발행)로 재설계하고, `vercel.json`에 4개 시간대 크론을 등록함. v1에 없던 기능도 추가: 새 글마다 다른 시드 페르소나의 업/다운보트(4~14명, 80% 업보트)와 짧은 시드 댓글(2~5개, 일부 대댓글·베스트댓글 고정(+10)·다운보트 접힘(-5) 임계치를 넘기도록 투표까지 자동 생성) — 핫스코어 정렬·베스트 댓글 고정·접힘 UI가 실제로 작동하는 것처럼 보이게 하기 위함.
  아직 QA/회귀 테스트가 안 끝난 단계라 실제 발행 시작 시점(런칭일)은 지금 정하지 않기로 함 — 환경변수 `SEED_DRIP_LAUNCH_DATE`가 Vercel에 설정되기 전까지 크론은 아무 것도 안 하고 조용히 종료하도록 만들어둠(크론 스케줄 자체는 등록돼 있어도 안전). `SEED_DRIP_LAUNCH_DATE`는 일단 2026-09-05로 잠정 설정(로컬 `.env.local`에만 반영, Vercel 대시보드에는 아직 미반영 — 사용자가 직접 등록 필요), 향후 QA 완료 시점에 맞춰 재조정 예정.
  런칭일 이전 클램프 버그(미래 런칭일을 설정해도 daysSinceLaunch 클램프 때문에 당일 즉시 Phase1이 발행되던 문제)를 `getTodayKst()` 명시적 문자열 비교로 수정 완료(commit `ce025b4`).
- **DB 레벨 드라이런 검증 (2026-08-02)**: 실제 크론을 실행하지 않고 읽기 전용 쿼리로 데이터 정합성만 확인 — 시드 페르소나 수 80명 일치, 룸별 미발행 잔여 풀이 인서트한 분포와 정확히 일치, `posts`/`comments`/`votes` 테이블이 모두 0건(조기 발행 없음 확인), 4개 결정형 플레어(`buy_or_not`/`should_i_buy`/`job_change`/`room_suggestion`)에만 `one_line_question`이 채워져 있음을 확인. 실제 엔드포인트를 호출해 글/투표/댓글이 실제로 생성되는 전체 사이클을 검증하는 라이브 테스트는 아직 미실시 — 로컬 샌드박스에서 `next dev`가 동작하지 않아 코드 레벨 실행이 불가능하고, Vercel 배포본에는 이번 세션의 최신 커밋이 아직 반영 안 됨(`git push` 필요).
- **남은 작업**: ① 사용자가 로컬에서 `git push`로 최신 커밋 배포 반영. ② Vercel 프로젝트 환경변수에 `SEED_DRIP_LAUNCH_DATE` 등록(현재 로컬에만 있음). ③ 필요 시 런칭일을 임시로 앞당겨 라이브 엔드포인트를 1회 트리거해보는 실제 통합 테스트(사용자 승인 필요 — 실제 글/투표/댓글이 DB에 생성됨). ④ 회귀 테스트/QA 완료 후 실제 런칭일 확정.
- **재검토 트리거**: 배포 반영 및 Vercel 환경변수 등록 후 라이브 테스트 여부를 사용자와 논의, 발행 시작 시점은 QA 완료 후 사용자가 직접 결정.
- **관련 코드**: `app/api/cron/seed-drip/route.ts`, `vercel.json`, `.env.local`/`.env.local.example`(SEED_DRIP_LAUNCH_DATE)

## 2. 룸/인기 피드 성능 — 구조적 지연 여지 남음

- **현황**: 룸 드롭박스로 룸을 바꿀 때 체감 지연이 크다는 리포트가 있어 확인해보니, (a) 서버 컴포넌트가 룸 조회·룸 목록·로그인 확인을 순차 await하고 있었고 (b) `loading.tsx`가 전혀 없어 응답을 기다리는 동안 화면이 멈춘 것처럼 보였음. 두 가지 모두 수정 완료(`app/room/[code]/page.tsx`·`app/page.tsx` 병렬 fetch로 변경, `app/loading.tsx`·`app/room/[code]/loading.tsx` 스켈레톤 추가).
- **결정 (2026-08-02)**: 애플리케이션 레벨에서 고칠 수 있는 부분은 처리 완료. 다만 Supabase 프로젝트 리전(ap-southeast-1)과 Vercel Hobby 플랜의 서버리스 콜드스타트는 구조적 요인이라 이번 작업으로 완전히 없어지지는 않음 — 사용자가 직접 배포 환경에서 체감 확인함(정상 작동 확인됨, 2026-08-02).
- **재검토 트리거**: 실사용자 유입 후에도 룸 전환 체감 지연이 반복적으로 불편하다는 신호가 있으면, ① Supabase 리전을 한국에 더 가까운 곳(현재 서울 리전 미지원 시 도쿄 등)으로 이전하거나 ② Vercel Pro로 업그레이드해 Edge/리전 옵션을 확보하는 방향을 검토.
- **관련 코드**: `app/page.tsx`, `app/room/[code]/page.tsx`, `app/loading.tsx`, `app/room/[code]/loading.tsx`, `lib/feed.ts`
