## 1. 스팸 격리 건 조회 (최근 50건)

목적: LLM이 스팸으로 판정한 글을 스팟체크하여 오탐(False Positive) 여부 확인.

```sql
SELECT
    p.id,
    p.created_at,
    p.user_id,
    pr.nickname,
    p.content,
    p.spam_reason
FROM posts p
LEFT JOIN profiles pr ON pr.id = p.user_id
WHERE p.is_spam = true
ORDER BY p.created_at DESC
LIMIT 50;
```

(원안 대비 `profiles.nickname`을 join해서 추가 — 작성자를 바로 식별할 수 있도록 함)

## 2. 재시도 3회 소진된 최종 실패 건 (system_error) 조회

목적: `app/api/cron/retry`가 최대 3회까지 재시도했으나 끝내 분류에 실패해 피드에서
계속 누락되고 있는 글 확인(수동 검토 대상).

```sql
SELECT
    p.id,
    p.created_at,
    p.retry_count,
    pr.nickname,
    p.content
FROM posts p
LEFT JOIN profiles pr ON pr.id = p.user_id
WHERE p.status = 'system_error' AND p.retry_count >= 3
ORDER BY p.created_at DESC;
```

## 3. 오늘 하루 AI 태깅 상태별 통계 (KST 기준, 수정본)

목적: LLM API 상태 및 전반적인 분류 성공률 모니터링.

**주의 — 원안(Gemini 제안)에는 KST 자정 계산 버그가 있었음**: `now() AT TIME ZONE 'UTC' AT
TIME ZONE 'Asia/Seoul'`은 자정을 자르지 않고 그냥 "지금 시각 - 9시간"을 반환해서, 시간대에
따라 날짜가 하루 밀리거나 우연히 맞는 간헐적 오류가 있었음(2026-07-25 21:12 KST 시점에
실제로 검증함). `date_trunc`로 먼저 자정을 자르고 그 다음 존 변환을 적용해야 정확함 —
`app/*/lib/date.ts`에서 지켰던 KST 계산 원칙과 동일.

```sql
SELECT status, count(*) AS count
FROM posts
WHERE created_at >= date_trunc('day', now() AT TIME ZONE 'Asia/Seoul') AT TIME ZONE 'Asia/Seoul'
GROUP BY status;
```
