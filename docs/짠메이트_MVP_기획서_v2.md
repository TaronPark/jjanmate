## 1. 피벗 배경 및 사업성 재검토

기존 v1의 핵심 차별화 전략은 "AI 초세분화 매칭"이었으나, 개발 막바지 UX/UI 정리 과정에서 다음 문제가 확인되어 사업성이 부족하다고 판단했습니다.

- AI 태깅의 실질 가치가 사용자에게 체감되기 어렵고, 운영 비용(LLM 호출)과 오분류 리스크만 누적되는 구조였음.
- 니치를 사전에 잘게 쪼개는 접근은 초기 콜드스타트(각 니치별 임계 사용자 수 확보)를 오히려 어렵게 만듦.
- 거지맵 등 경쟁 서비스가 이미 인증/커뮤니티 기능을 흡수하고 있어, "AI 매칭"만으로는 차별화 축이 약함.

이에 따라 짠메이트는 **"레딧형 자정작용 커뮤니티"** 모델로 전면 전환합니다. 사용자가 직접 룸(카테고리)과 플레어(세부 태그)를 선택해 글을 쓰고, 업보트/다운보트와 핫스코어 랭킹으로 콘텐츠 품질이 커뮤니티 자체적으로 정렬되는 구조입니다. AI 분류 의존을 없애 운영 비용·오분류 리스크를 제거하는 동시에, 투표·플레어·배지 등 레딧/디시인사이드류 커뮤니티에서 검증된 참여 메커니즘으로 재미와 체류시간을 확보하는 것이 새 차별화 축입니다.

거지맵 대비 포지셔닝은 유지됩니다: 거지맵이 "지출 인증 지도앱"이라면, 짠메이트는 "절약 경험을 텍스트/이미지로 나누고 서로 평가·토론하는 커뮤니티"로 뾰족하게 남습니다.

## 2. MVP 컨셉 재정의

- **6개 고정 룸**: 사전 정의된 6개 메인 룸으로 구성(니치 무한 확장 대신 소수 고정 카테고리로 콜드스타트 리스크 최소화).
- **룸당 4개 플레어(총 24개)**: 글 작성 시 룸 + 플레어를 사용자가 직접 선택. 플레어별로 투표 버튼 문구가 동적으로 바뀌어(예: 공감/인정 등) 맥락에 맞는 참여를 유도.
- **업보트/다운보트 + 핫스코어**: Raw Hot Score와 Popular Hot Score 이원화, 시간감쇠 지수(γ=1.2), 룸별 가중치(W_room, 0.5~2.0 캡), 콜드스타트 보호(신규 글 노출 부스트), 최대 노출시간 컷오프로 랭킹 산정.
- **1뎁스 스레드 댓글**: 대댓글은 1단계까지만 허용. 베스트 댓글 고정(+10 이상), 다운보트 누적 시 자동 접힘(−5 이하).
- **1클릭 작성자 상태(4종 고정 플레어)**: 글 상단에 작성자가 원클릭으로 남기는 상태 표시.
- **유저 플레어**: 자유입력 최대 5자, 블랙리스트 검증(부분일치+정규화 매칭)으로 부적절 표현 차단.
- **월간 배지/보상**: 포인트·환금성 없는 명예 배지 — 룸별 TOP3(왕관/별) + 전체 TOP3(글로우 오버라이드), 매월 스냅샷 후 리셋. 사행성 규제 리스크를 원천 차단하는 설계.
- **북마크**: 다중 탭존(글 목록/상세 어디서든 원터치 저장).
- **초안 자동저장**: 24시간 만료, 30초 간격 자동저장, 유저당 1개 초안.
- **전체화면 글쓰기 모달**: 플레어 종류에 따라 3단계/2단계/1단계로 입력 흐름이 달라지는 컨텍스트형 작성 UX(예: 투표형 플레어는 "한줄질문" 필드 추가, 이미지 플레어는 4:5 캐러셀).
- **마이페이지 4탭**: 게시글/댓글/북마크/보상명예 + 별도 설정 드로어.

**폐기 확정 기능** (2026-08-01 사용자 확인):
- 스트릭 유지 기능 (`lib/streak.ts`) — 전면 폐기.
- 매칭 프리뷰(니치 매칭 미리보기, `matching_previews` 테이블 및 `/preview` 화면) — 전면 폐기.
- AI 자동분류 파이프라인 전체(`lib/ai/classifyPost.ts`, `/api/tags`, 재시도 큐) — 전면 폐기.
- 니치 기반 피드 구조(`/feed/[niche]`) — 룸 기반 피드로 대체.
- 리액션(cheer/me_too 2종) — 업보트/다운보트로 대체.

## 4. 기능 범위 (MoSCoW)

**Must (MVP 필수)**
- 6개 룸 + 24개 플레어 고정 데이터
- 글쓰기(룸/플레어 선택, 컨텍스트별 입력, 이미지 첨부, 초안 자동저장)
- 업보트/다운보트 + 핫스코어 랭킹(Raw/Popular)
- 1뎁스 댓글 + 베스트 댓글 고정 + 다운보트 접힘
- 1클릭 작성자 상태(4종)
- 유저 플레어(자유입력 5자, 블랙리스트 검증)
- 북마크
- 마이페이지 4탭 + 설정
- 카카오 로그인(기존 유지)

**Should (MVP 이후 빠른 후속)**
- 월간 배지/보상 스냅샷 배치 + 축하 UX
- 룸별 TOP3 / 전체 TOP3 노출

**Won't (이번 MVP 범위 제외, 명시적 폐기)**
- AI 자동분류/매칭 프리뷰
- 스트릭
- 포인트·쿠폰 등 환금성 보상
- 다국어, 성인인증

## 6. 수익 모델 (재검토)

- 구 문서의 "짠포인트 → 커머스 할인쿠폰 전환" 아이디어는 폐기합니다. 신규 모델의 배지/보상은 명시적으로 **환금성 없는 명예 보상**으로 설계되어 있어(사행성 규제 회피가 설계 의도), 포인트 경제 자체가 존재하지 않습니다.
- 카카오뱅크 26주적금 등 금융 제휴 모델은 룸/플레어 구조와 독립적인 아이디어이므로 전략적으로는 여전히 유효합니다. 다만 MVP 범위 밖이며, 실제 도입 시점에는 "절약 인증 콘텐츠 상단 배치" 등 새 UI에 맞는 제휴 노출 방식을 다시 설계해야 합니다.
- 본 문서는 MVP 단계 수익모델을 확정하지 않습니다 — 유저 참여 지표가 쌓인 이후 재논의가 필요합니다.

## 7. 리스크 (갱신)

**폐기(더 이상 해당 없음)**
- LLM 태깅 비용/정확도 리스크
- 프롬프트 인젝션 리스크
- 니치 세분화로 인한 콜드스타트 리스크(니치 자체가 6개 고정 룸으로 축소되어 완화)

**유지(여전히 유효)**
- 거지맵 등 경쟁 서비스의 기능 확장 리스크
- 소셜로그인 카카오 단일화 리스크
- Vercel Hobby 플랜의 크론/함수 실행시간 제약 — 특히 월간 배지 스냅샷 배치, 핫스코어 재계산 배치를 고려하면 재검토 필요

**신규 (피벗으로 인해 새로 발생)**
- 투표 조작/봇 어뷰징 리스크 — 핫스코어 알고리즘이 조작에 취약할 경우 랭킹 신뢰도 붕괴
- 콘텐츠 모더레이션 부담 — 사용자 자유 게시(정치/혐오 표현 등) 관리 체계 필요, 신고/제재 플로우 미정
- 유저 플레어 블랙리스트 관리 리스크 — 우회 표현(자모 분리, 특수문자 삽입 등) 대응 지속 필요
- 6개 룸 간 활성도 불균형 리스크 — 특정 룸으로 쏠림 시 나머지 룸 콜드스타트 지속
